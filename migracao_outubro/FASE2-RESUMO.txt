  REGRAS-NEGOCIO-CASOS.md (10 KB)
  ├─ Workflow Completo de Casos
  │  ├─ 10 Estados: PENDENTE → ... → CASO_FINALIZADO ou CANCELADO
  │  ├─ Transições Manuais (MVP): usuário avança status via API
  │  ├─ Validações por Estado: condições antes permitir transição
  │  └─ Exemplo Fim-a-Fim: caso do ajuizamento até crédito gerado
  │
  ├─ Banco de Dados (Schema)
  │  ├─ tb_casos: processo, vara, juiz, status, datas, pessoas
  │  └─ tb_historicos: auditoria de cada ação (quem, quando, o quê)
  │
  ├─ Validações
  │  ├─ Criação: processo_id único, vara obrigatória, data válida
  │  ├─ PENDENTE → COLETA_AGENDADA: deve ter responsável e coletador
  │  ├─ COLETA_REALIZADA → AMOSTRA_RECEBIDA: amostra não vencida
  │  ├─ EM_EXTRACAO → EXTRACAO_CONCLUIDA: validador aprova, alelos documentados
  │  ├─ EXTRACAO_CONCLUIDA → EM_ANALISE: médico designado
  │  ├─ EM_ANALISE → LAUDO_EMITIDO: parecer + comparação genética
  │  └─ LAUDO_EMITIDO → CASO_FINALIZADO: créditos gerados
  │
  ├─ Permissões (Roles)
  │  ├─ admin: criar, atualizar, deletar, cancelar qualquer caso
  │  ├─ gestor_casos: criar, atualizar, cancelar, avançar status
  │  ├─ coletador: confirmar coleta realizada
  │  ├─ tech_extracao: iniciar extração, validar resultado
  │  ├─ medico: emitir laudo, finalizar análise
  │  └─ usuario_comum: apenas visualizar (próprios)
  │
  ├─ Histórico & Auditoria
  │  ├─ Cada ação gera registro em tb_historicos
  │  ├─ Tipos: CRIACAO, STATUS_ALTERADO, COLETA_CONFIRMADA, ..., CANCELAMENTO
  │  ├─ Rastreia: quem, quando, o quê, antes/depois (se status)
  │  └─ Permite reverter ações (audit trail completo)
  │
  ├─ Créditos (Gatilho)
  │  ├─ Quando caso → CASO_FINALIZADO, gera parcelas para cobrança
  │  ├─ Crédito para: Coletador, Técnico Extração, Médico Analista
  │  ├─ Valores por tipo análise (DNA, Paternidade, etc)
  │  ├─ Aplicar descontos/taxas (juiz, vara, categoria)
  │  └─ Reverter se caso cancelado
  │
  ├─ Notificações
  │  ├─ Caso Criado → Responsável
  │  ├─ Coleta Agendada → Coletador
  │  ├─ Amostra Recebida → Tech Extração
  │  ├─ Extração Concluída → Médico
  │  ├─ Laudo Emitido → Gestor
  │  └─ Caso Finalizado → Todos (créditos gerados)
  │
  ├─ Casos Especiais
  │  ├─ Caso sem coletador: avisar, agendar lembrança
  │  ├─ Amostra vencida: marcar cancelado, motivo "AMOSTRA_VENCIDA"
  │  ├─ Extração inconclusiva: permitir nova coleta ou cancelar
  │  └─ Laudo com conflito genético: aviso + email para juiz/advogados
  │
  └─ Queries Comuns (Repository)
     ├─ findById, findByProcessoId, findAll
     ├─ findByVara, findPendentes, findEmAndamento, findFinalizados
     ├─ search(filtros), create, update, cancel

✅ DECISÕES CONFIRMADAS

  ✓ Monolito único (não microserviços)
    └─ SCEI como "bounded context" dentro da mesma aplicação

  ✓ Transições manuais no MVP
    └─ Automação de tarefas é "future" com job queues

  ✓ Auditoria completa via events + histórico
    └─ Rastrear todas as ações de usuário

  ✓ JWT tokens com Sanctum
    └─ 24h expiração, 7d refresh tokens

  ✓ Bcrypt para senhas
    └─ Migration helper: criptografa senhas antigas do Firebird

  ✓ Validações em Form Requests
    └─ Não em models (separação de responsabilidades)

  ✓ Service Layer para regra de negócio
    └─ Controllers → Services → Repositories (3 camadas)
